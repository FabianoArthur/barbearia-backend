## TECH STACK
================================================================================

Runtime:          NestJS + Prisma + PostgreSQL 17
Auth:             JWT (access + refresh tokens) with cookie-based transport
Queue/Jobs:       BullMQ (Redis-backed)
Caching:          Redis 7 via cache-manager-ioredis-yet
Real-time:        Server-Sent Events (SSE)
WhatsApp:         Twilio and Z-API provider implementations
API Docs:         Swagger/OpenAPI at /docs
Validation:       class-validator + class-transformer (runtime), Biome (lint/format)
Security:         bcrypt, CSRF guard, ThrottlerModule (20 req/60s), AES-256 encryption
Containerization: Docker Compose (PostgreSQL 17 + Redis 7-alpine)

## DATA MODELS (Prisma)
================================================================================

Enums:
  Role:              BARBER, MANAGER, SUPER_ADMIN
  AppointmentStatus: SCHEDULED, CONFIRMATION_PENDING, CONFIRMED, IN_PROGRESS,
                     DONE, CANCELED, NO_SHOW
  FeeType:           PERCENTAGE, FLAT, TIERED, HYBRID
  PaymentMethod:     CASH, PIX, CREDIT_CARD, DEBIT_CARD
  PaymentStatus:     PENDING, COMPLETED, REFUNDED, FAILED
  ExpenseCategory:   RENT, SUPPLIES, UTILITIES, MAINTENANCE, SALARY, OTHER

Models:
  User, RefreshToken, Establishment, Barber, Client, Service,
  Appointment, BarberWorkingHour, BarberTimeOff, BarberScheduleOverride,
  AppointmentAuditLog, AuditLog, PlatformFeeConfig, Payment, Expense

Key relations:
  User        -> Establishment (optional), Barber (1:1), RefreshToken (1:N)
  Barber      -> Establishment, Services (M2M), WorkingHours, TimeOffs, Overrides
  Client      -> Establishment, Appointments
  Service     -> Establishment, Barbers (M2M)
  Appointment -> Establishment, Barber, Client, Service, Payment (1:1), AuditLogs
  Payment     -> Appointment (1:1), Establishment
  Expense     -> Establishment, Barber (optional)
